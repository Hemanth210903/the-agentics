│  Retrieval‑augmented generation (RAG) is a way to make AI text generators more reliable by letting them look up             │
│  information before they write. Imagine a writer who first searches a library for relevant articles, then uses those        │
│  articles as notes while drafting a response. In a RAG system two parts work together. The first part, called the           │
│  retriever, scans a large collection of documents—news stories, manuals, web pages—and pulls out a handful of passages      │
│  that seem related to the question. The second part, a generative language model, reads those passages and uses them as     │
│  context to produce its answer. Because the answer is grounded in real text, the system is less likely to hallucinate       │
│  facts and can stay up‑to‑date simply by adding new documents to the index, without retraining the model.                   │
│                                                                                                                             │
│  Experiments show that this hybrid design beats plain generators on tasks that need current or specialized knowledge. For   │
│  example, on the Natural Questions test, a RAG model improved exact‑match scores by about 12 % compared with the same       │
│  model that did not retrieve anything. Techniques such as “fusion‑in‑decoder” feed each retrieved passage separately into   │
│  the generator, helping it combine multiple sources effectively.                                                            │
│                                                                                                                             │
│  Companies have already packaged RAG into products—Microsoft’s Azure OpenAI, Anthropic’s Claude with a search tool, and     │
│  Cohere’s RAG‑API—so developers can build chatbots that answer customer queries using a company’s own knowledge base.       │
